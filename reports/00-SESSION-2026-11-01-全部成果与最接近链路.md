## 二、开发者令牌（libsecret-lib.so）：算法还原 + 实机验证通过

### 2.1 算法（arm64-v8a 未 strip 反汇编 + DWARF）

```
newDt():
  raw = "!@#xuehai3" + hour + "&zhitongyun3" + mon + "$100fen!@#" + YEAR + "@" + MDAY
  s = MD5( base64(raw) + "\n" )
  s = changeToken(hour, s, reverse=true)      // 奇偶筛选取半
  for i in 0..hour:                            // hour+1 次
      odd = (i % 2 != 0)
      s = changeToken(hour, MD5(base64? s : s), odd)
```

**修正了此前公开分析的 year/mday 顺序错误**（年份在日期之前）。

### 2.2 实机验证

- `LoginViewModel$login$1` 传 `type=1` → `MdmBinder.verifyDynamicToken(key,1)` → `SecretJni.verifyQrToken`（取前 8 位）
- **2026-11-01 11:2x 实机**：8 位令牌填入登录「账号名」→ **不再报账号/密码错误，走了开发者分支**（`reqScanAbility`）
- 16 位全令牌 = `verifyDevelopToken(type=0)` = DeveloperActivity 的 token，同样可离线算出

### 2.3 到达功能边界

```
令牌通过 → reqScanAbility()
  → GET /api/v1/platform/{deviceId}/scan/ability（https 真实服务器）
  → 服务端返回 Boolean → _showQRScanner
  → 实测服务端返回 false / 扫码器依赖外部 ZXing 未安装
```

**令牌可伪造（已实机验证），但唯一到达的是「扫码能力」，服务端开关是最终闸门。**

## 三、IP 绕过：从疑似到确证

### 3.1 代码依据

- `XHHostnameVerifier.verifyIpAddress()` **无条件 return true**
- `OkHttp 3.12.1 RealConnection.connectTls`（smali 380-392）：

```smali
v5 = address.hostnameVerifier()
v6 = address.url().host()      // ← 取自 HttpUrl，不是 socket 远端地址
verify(v6, session)
```

**⇒ 仅当 URL host 本身是 IP 字面量时绕过生效；域名 URL（ztp）仍正常校验。**

### 3.2 实机证据（抓包）

```
11:41:36  SYN dst=192.168.137.1:443   CH sni=ztp.yunzuoye.net    ← DNS 劫持到本机
11:41:43  SYN dst=47.111.87.154:443   CH sni=ztp.yunzuoye.net    ← 真实 IP + 域名 SNI
11:41:43  CH  dst=47.111.87.154:443   sni=<NO-SNI>  ★★★          ← URL host = IP，绕过生效
```

**App 用阿里 HTTPDNS（203.107.1.1 / account 103172）解析真实 IP，绕过 DNS 劫持；但 App 确实会以 `https://<IP>` 形式发起请求。**

## 八、当前最接近 100% 全自动接管链路的方案

### 方案 A（当前最接近）：MITM 伪造登录 → 业务页 → assist

```
① 平板连真实 IP:443（无 SNI，URL host=IP）
② 本机 IP 别名认领（已配好 47.99.85.219/47.111.87.154/47.110.67.143）★已自测通过
③ MITM 用 Let's Encrypt 证书终止 TLS（verifyIpAddress 绕过放行）★已自测通过
④ 登录请求明文可见 → 返回伪造 activated:true + accessToken（含 X-Content-Sign-Token 签名）
⑤ App 认为登录成功 → 进入主页 → 发起业务请求（ms.yunzuoye.net 明文 http，嗅探器已接管）
⑥ assist 链路：REMOTE_ASSIST → /assists/{id}/tasks → executeCmd → 命令执行
```

**当前瓶颈：**
- **平板 Wi-Fi 掉线**（本轮实测 ping 不通、30 秒零出站流量）—— 需先恢复热点连接
- 登录请求若走**域名** `ztp.yunzuoye.net`（有 SNI），无法 MITM（证书主机名不匹配）；**只有走 IP 字面量的请求可拦**（抓包已证实存在此类请求，但需确认登录本身是否走 IP）
- 伪造登录后 App 的后续请求（用户信息/权限/数据码）能否全部伪造成功，待实测

### 方案 B：设置主界面 → 开发者选项 → USB 调试（需 UI 可达）

`com.android.settings.Settings` 主界面与 `DevelopmentSettingsDashboardActivity` 均未在 P200 禁用列表。
**若平板能打开「设置」→ 关于 → 连点 7 次版本号 → 开发者选项 → USB 调试 → ADB** —— 这是最直接的物理接管路径。
**本轮实测：用户反馈「开不来开发者」**（Settings 入口不可达或开发者选项被 ROM 层隐藏）。

### 方案 C：com.samsung.customxh.CustomDeviceService（需第三方 App）

若该 ROM 服务 exported 且无签名权限限制，第三方 App 可直接调 `setUsbDebugEnabled(true)`/`reboot`。
**前提：需要能在平板安装一个 App（当前无安装通道）。**

### 方案 D：开发者令牌 → 扫码能力（已验证，但服务端闸门）

令牌可伪造，但 `scan/ability` 服务端返回 false。
